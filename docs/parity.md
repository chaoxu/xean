# Xean capabilities

This inventory maps implemented behavior to its code and focused tests. The
[README](../README.md) gives entry points, check commands, and live qualification
limits. Pi owns execution and storage. Xean adds research policy, mathematical
verification, and operator interfaces through native tasks and documents.

This checkout develops 3.5.0 with changed campaign definitions and external role
interfaces. Start fresh campaigns and retain existing campaigns' frozen runtimes.
No migration is provided. Historical qualification and measurements below retain
their original runtime provenance.

## Pi integration

Pi preserves rotated OAuth tokens after cancellation and retries HTTP/2 requests
whose pending stream was cancelled. These use native provider behavior.

The CLI uses Pi's `builtinModels` with coding-agent's `AuthStorage` for persistent
credentials and refresh locking. Login and logout use the bundled Pi CLI.
Reasoning levels use Pi's native configuration schema.
Xean supplies frozen settings and uses Pi's built-in model catalog, with no Pi
model-file loading or startup catalog refresh. The default library setup accepts caller-owned
`Models` and does not load a user's credentials by default.

Native tasks, tool controls, session resource cleanup, provider authentication,
and SQLite configuration supply the execution behavior. Structured submissions
stay in Pi tool-result details. Only note reads override output limits to preserve
complete text. The patched request hook preserves Pi's default stream and model
context when an extension supplies no replacement. Xean uses raw entries at the
request cutoff for role guards. Pi supplies the model transcript and validates
submissions against the registered static tool schemas.
Xean enforces exact assigned IDs and available worker choices from the frozen
assignment when the submission executes.

Private role conversations have no edits or compaction. Their raw entries retain
failed responses. Pi's context projection orders tool results and places the
initial system message first. The continuation patch converts incomplete tool
calls to draft text before missing-result synthesis.
Fallible setup runs inside the stream so a failure prevents dispatch. Role
allowances derive from the committed transcript and frozen assignment. Explorer
retains its configured completed-response and read limits. Other native role
conversations default to sixteen completed responses, with four admitted reads
for Coordinator. Rejected submissions consume responses, while incomplete
responses do not. Pi supplies
context-range caching, response, tool, and task timing,
ascending history scans, request retries, checkpoints, and scheduling.
Pi bounds scheduler ownership metadata by live work. Xean sets native
`documentRetentionMs` to zero so unobserved document trackers leave the cache
after use. Observed documents remain cached until their observers detach or the
document retires.
Each campaign Verifier uses the note view frozen by its Coordinator decision and
reuses completed PASS checks, including those on shared dependencies. Pi task
waits keep the next decision behind the complete worker outcome.
Checks bind the assessed argument, exact statements, and premises. Notebook edits
can change applicability. Coordinator can select an external Verifier to reassess an
INCONCLUSIVE correctness, requirements, or reconstruction check, including after
a prior external assessment. These checks have no automatic retry. Immutable worker
requests and execution receipts retain provenance. New source evidence bound to
the exact premises can reopen an eligible INCONCLUSIVE source check.

Every changed Explorer or caller edit advances the note revision. Changed
mathematical fields reopen affected checks. Candidate and retirement flags only
advance the revision. Explorer mathematical edits revoke external trust.

Inspection opens the existing database with SQLite `query_only` and holds a
read transaction for the complete callback. Pi checks the schema version without
migrations and rejects writes and ID allocation. Closing rolls back the read
transaction and skips the explicit WAL checkpoint. This path uses a Session
without a Harness or work recovery. SQLite may maintain WAL sidecars, so inspection
requires a writable database location.
CLI `status`, `inspect`, and `export` use this path directly.

The current notebook lives in a rewindable Pi catalog and per-note body Documents.
Initialization creates the catalog atomically with campaign control. Databases
without a catalog require their frozen runtime. Each native Explorer submission
updates the notebook and its task-scoped replay receipt in one Pi commit.
Worker completion records publication references. A later failure or cancellation
retains committed batches, and recovery returns the saved receipt without
publishing twice. Worker events use native `byTaskId` attribution. Outcomes retain
full verification receipts, while the catalog references current checks. Readers use
current or frozen Documents rather than replaying all worker outcomes. Acceptance
pins a snapshot Entry for historical export. Native model transcripts remain
unchanged.

Xean registers Pi's public `resetOpenAICodexWebSocketDebugStats` with
`registerSessionResourceCleanup`. Ordinary role cleanup then releases Codex
diagnostics and fallback state through native APIs. The session cleanup test in
[Pi tests](../tests/pi.test.ts) checks that the same session can attempt WebSocket
again after cleanup.

The CLI resolves Pi's installed entry point and loads its pinned `AuthStorage`
module directly. This reuses native credentials without loading interactive
exports or patching the package manifest. The module path is checked when
updating Pi and packaging Xean.

Native document retention controls idle lifetime. Watched documents and active
commits still use memory. Evicted documents reload from storage, and active
observers continue receiving committed changes.
[Provenance](../vendor/pi/provenance.json) records artifact and patch hashes.
The clean distribution install runs Pi and role contract tests against the patched
packages.

Native retry defaults remain in effect. Role allowances count completed responses.
Submission tools prefer Pi's JSON-schema constrained sampling. Pi falls back
when a provider or schema does not support it. Local result validation still applies.
External CLI output uses Pi's argument validation. Codex implementation and
verification use Pi's strict-schema conversion, with optional fields returned as
null normalized before validation.
The adapters classify `max_messages` and `max_output_tokens` as incomplete
responses. Pi also recognizes `stream disconnected before completion` and
`stream closed before response.completed` as retryable errors. Limits and
retryable errors with reusable text, reasoning, or tool arguments share the same
automatic continuation, with no fixed count. Pi atomically retains the raw response,
adds continuation input, and schedules the next generation. Tool arguments become
unexecuted draft text. Incomplete tools never execute. Queued follow-ups wait for
the complete answer, while steering can reach the next generation. Empty limit
responses fail explicitly. Retryable errors without reusable output use the native
retry budget and backoff. Authentication, quota, invalid-request failures, context
overflow, and cancellation retain their existing handling.

Continuation history preserves text and tool drafts from output limits and
retryable errors, including across API, provider, or model changes. Interrupted
text signatures are stripped.
Encrypted OpenAI Responses reasoning from failed responses requires valid
completed-item signatures from the same API, provider, and model. The projection validates those signatures
and deduplicates item IDs. Raw errors remain in the transcript.
At context or completed-response exhaustion, Explorer may hand off earlier
complete submissions with the operational reason. Completed verification stages
remain recoverable, and mathematical acceptance rules are unchanged. These
limits impose no campaign call ceiling.

Gateway WebSocket caches are omitted. Ordinary diagnostic reports remain
nonfatal. Storage failures and scheduler bookkeeping failures use Pi's native
Session failure path. The host waits for native closure before releasing database
ownership and preserves the original failure if cleanup also fails.
