# Xean capabilities

This inventory maps implemented behavior to its code and focused tests. The
[README](../README.md) gives entry points, check commands, and live qualification
limits. Pi owns execution and storage. Xean adds research policy, mathematical
verification, and operator interfaces through native tasks and documents.

Run this release on fresh campaigns. Open existing databases with their frozen
runtimes. Historical qualification and measurements below retain their original
runtime provenance.

## Pi integration

Pi preserves rotated OAuth tokens after cancellation and retries HTTP/2 requests
whose pending stream was cancelled. These use native provider behavior.

The CLI uses Pi's `builtinModels` with coding-agent's `AuthStorage` for persistent
credentials and refresh locking. Login and logout use the bundled Pi CLI.
Reasoning levels use Pi's native configuration schema.
Xean supplies frozen settings and uses Pi's built-in model catalog, with no Pi
model-file loading or startup catalog refresh. The core library accepts caller-owned
`Models` and does not load a user's credentials by default.

Native tasks, tool controls, session resource cleanup, provider authentication,
and SQLite configuration supply the execution behavior. Structured submissions
stay in Pi tool-result details. Only note reads override output limits to preserve
complete text. The patched request hook preserves Pi's default stream and model
context when an extension supplies no replacement. Xean's private role
conversations use raw entries at the request cutoff for guards and reasoning
recovery. Pi validates submissions against the registered static tool schemas.
Xean enforces exact assigned IDs and available worker choices from the frozen
assignment when the submission executes.

Private role conversations have no edits or compaction. Their raw entries retain
failed responses. The projection preserves raw message order, bypasses Pi's
leading-system-message adjustment, and excludes truncated tool calls before
missing-result synthesis.
Fallible setup runs inside the stream so a failure prevents dispatch. Yield
continuations derive their allowances from the committed transcript and frozen
assignment. Explorer retains its configured response and read limits. Other
native role conversations default to sixteen responses, with four admitted reads
for Coordinator. Rejected submissions consume responses. Pi supplies
context-range caching, response, tool, and task timing,
ascending history scans, request retries, checkpoints, and scheduling.
Each campaign Verifier uses the note view frozen by its Coordinator decision and
reuses completed PASS checks, including those on shared dependencies. Pi task
waits keep the next decision behind the complete worker outcome.
Checks bind the assessed argument, exact statements, and premises. Notebook edits
can change applicability. Completed non-PASS assessments of unchanged inputs
remain unresolved without scheduling them again. New source evidence bound to the
exact premises can reopen an eligible INCONCLUSIVE source check.

Explorer and caller edits can declare `cosmetic: true` for presentation-only
text changes. Xean trusts this flag and preserves the mathematical revision,
checks, and import trust while advancing the public revision for changed text.
Support changes always invalidate affected checks. When private edits to a note
merge, a mathematical text edit keeps the merged text edit classified as
mathematical. Cosmetic edits alone leave an INCONCLUSIVE assessment closed.

Inspection copies existing databases through SQLite `query_only`, which rejects
SQL writes while allowing SQLite to maintain WAL sidecars. Pi opens the disposable
copy and checks its schema. Inspection requires a writable database location,
supports stopped WAL databases after their sidecars have been removed, and never
runs a Harness or recovers work.

The current notebook lives in a rewindable Pi catalog and per-note body Documents.
Publication updates notebook state and the native worker outcome atomically.
Worker events use native `byTaskId` attribution. Outcomes retain full verification
receipts, while the catalog holds references to current checks.
Native-tool Explorer submissions remain private until publication. After a
terminal provider failure, earlier validated submissions can publish through
their Pi Entry references if they still validate against the current notebook.
Successful publication records the failed worker outcome and error. Readers use
current or frozen Documents rather than replaying all worker outcomes. Acceptance
pins a snapshot Entry for historical export. Native model transcripts remain
unchanged. Earlier databases require their frozen runtimes.

Xean registers Pi's public `resetOpenAICodexWebSocketDebugStats` with
`registerSessionResourceCleanup`. Ordinary role cleanup then releases Codex
diagnostics and fallback state through native APIs. The session cleanup test in
[Pi tests](../tests/pi.test.ts) checks that the same session can attempt WebSocket
again after cleanup.

The CLI resolves Pi's installed entry point and loads its pinned `AuthStorage`
module directly. This reuses native credentials without loading interactive
exports or patching the package manifest. The module path is checked when
updating Pi and packaging Xean.

The tracker limit bounds document count, not bytes. Evicted documents reload from
storage, and active observers continue receiving committed changes.
[Provenance](../vendor/pi/provenance.json) records artifact and patch hashes.
The clean distribution install runs Pi and role contract tests against the patched
packages.

Native retry defaults and response-based accounting remain in effect.
Submission tools prefer Pi's JSON-schema constrained sampling. Pi falls back
when a provider or schema does not support it. Local result validation still applies.
Message-limit recovery replays only completed encrypted reasoning from the same
API, provider, and model. Pi attaches reasoning signatures at completed-item
events. The projection validates those signatures and deduplicates item IDs,
while the original failure remains in the transcript.

Output-token truncation uses Pi's `onYield` hook to continue the same assignment.
Pi commits the truncated response, continuation, and next generation atomically.
Each private conversation permits eight token-limit continuations, separately
from native error retries and within any role response allowance. At that limit
or context exhaustion, Explorer may hand off earlier complete submissions.
The truncated response contributes no submission. Completed verification stages
remain recoverable, and mathematical acceptance rules are unchanged. These
allowances impose no campaign call ceiling. ChatGPT Web remains a single request.

Gateway WebSocket caches are omitted. Ordinary diagnostic reports remain
nonfatal. Storage failures and scheduler bookkeeping failures use Pi's native
Session failure path. The host waits for native closure before releasing database
ownership and preserves the original failure if cleanup also fails.
