# Xean capabilities

This inventory maps implemented behavior to its code and focused tests. The
[README](../README.md) gives entry points, check commands, and live qualification
limits. Pi owns execution and storage. Xean adds research policy, mathematical
verification, and operator interfaces through native tasks and documents.

## Pi integration

Pi preserves rotated OAuth tokens after cancellation and retries HTTP/2 requests
whose pending stream was cancelled. These use native provider behavior.

Native tasks, tool controls, session resource cleanup, provider authentication,
and SQLite configuration supply the execution behavior. Structured submissions
stay in Pi tool-result details. Only note reads override output limits to preserve
complete text. A Pi Durable patch lets
`beforeRequest` select a stream and read the raw active entries at the request
cutoff. Profiles use this hook for request options, guards, and reasoning recovery.
The hook also derives submission ID enums from the frozen assignment. Pi retains
the static tools, and submission validation enforces exact assigned IDs.
The raw entries retain failed responses that Pi omits from its model context.
Private role conversations use these entries without edits or compaction.
The projection excludes truncated tool calls before any missing-result synthesis.
Remove the hook patch when Pi exposes these inputs and stream selection natively. Fallible
setup runs inside the stream so a failure prevents dispatch. Pi continues to own
request retries, checkpoints, and scheduling.
Each campaign Verifier uses the note view frozen by its Coordinator decision and
reuses completed PASS checks, including those on shared dependencies. Pi task
waits keep the next decision behind the complete worker outcome.
The first correctness PASS fixes the extracted statement and premise list.
A null statement is final for that note. A committed source verdict also fixes
its original premise binding.

Default inspection copies existing databases through SQLite `query_only`,
which rejects SQL writes while allowing SQLite to maintain WAL sidecars.
Live inspection permits Pi's initialization and document-read transactions
on the original database, but rejects logical commits and schema migrations.
Both modes require a writable database location, support stopped WAL databases
after their sidecars have been removed, and never run a Harness or recover work.

The Pi AI patch repairs behavior inside provider adapters:

- Preserve structured errors and classify retries by status and provider codes.
- Recognize the exact Responses `incomplete.max_messages` reason for native retries.
  Authentication, quota, context, and invalid-request failures remain terminal.
- Retain direct Codex error identity through native HTTP and WebSocket fallback.
- Parse valid Codex SSE streams with CRLF line endings.
- Retain reported failed-response usage and distinguish explicit zero usage.

The application cannot recover errors or usage discarded by an adapter. Repairing
those losses outside Pi would duplicate provider parsing and normalization.
[Provenance](../vendor/pi/provenance.json) binds both patches and installed files to
the original archives. The dependency check verifies both changed and untouched
files.

Native retry defaults and response-based accounting remain in effect.
Submission tools prefer Pi's JSON-schema constrained sampling. Pi falls back
when a provider or schema does not support it. Local result validation still applies.
Message-limit recovery replays only completed encrypted reasoning from the same
API, provider, and model. Pi attaches reasoning signatures at completed-item
events. The projection validates those signatures and deduplicates item IDs,
while the original failure remains in the transcript.

Output-token truncation uses Pi's `onYield` hook to continue the same assignment.
Pi commits the truncated response, continuation, and next generation atomically.
Each private conversation permits eight token-limit continuations, separately
from native error retries and within any role response allowance. At that limit
or context exhaustion, Explorer may hand off earlier complete submissions.
The truncated response contributes no submission. Completed verification stages
remain recoverable, and mathematical acceptance rules are unchanged. These
allowances impose no campaign call ceiling. ChatGPT Web remains a single request.

Gateway WebSocket caches are omitted. Native
reports do not identify every scheduler failure separately from nonfatal
extension reports. The host's health check detects poisoned Sessions, while
healthy-session scheduler failures remain diagnostic.

The source baseline was the Xean working tree at revision
`6ff5c861e53825e55c72d83802c7a58b27e2e932`, including its unpublished changes.
Its published `origin/main` was `50c147a99b66f6abda779b1bddbf2653bab2c73c`.
Reference paths were `README.md`, `docs/solver.md`, `docs/kernel.md`,
`docs/glossary.md`, and `packages/observe/README.md`. Native interfaces and formats
replace the former implementation. Historical campaigns retain their original
readers and runtimes.
