# Elenx 0.10.0 and elenx-solve 0.36.0

These notes describe the published `v0.10.0` packages. For current source behavior and compatibility, see the [Solver README](../../packages/solve/README.md) and [kernel specification](../../SPEC.md).

Elenx 0.10.0 adds durable intake for mathematical notes and clearer recovery evidence. Solver 0.36.0 adds opt-in same-context Explorer continuation with a bounded context budget and fresh user directions after nonterminal submissions.

## Supply work to a campaign

Use `submit [--id ID] CAMPAIGN.db NOTES.json` to append caller-supplied notes without making a model request. Each note keeps its text exactly and names existing live notes as structured support. An optional external verification attestation identifies the reviewer and its basis. It can make a note available as verified support when its support is verified, while acceptance still requires the four normal verifiers. `inspect --include-submissions` reports receipts, delivery boundaries, assigned note IDs, and pending submissions.

The coordinator receives supplied notes at the next unfrozen intake boundary. Notes submitted before the first Explorer turn can be filed and verified before exploration, so a complete supplied proof can be accepted with zero Explorer turns after the normal checks pass. Notes submitted during an Explorer turn are numbered after that turn's saved notes and delivered before its next coordinator input.

`guide --id ID CAMPAIGN.db GUIDANCE.txt` remains available for fallible advice to a future Explorer turn. Guidance is delivered once per turn, including retries, and never changes the task, completion criteria, verifier authority, or turn cap.

## Explorer continuation

Set `explorerContinuation` to `true` to let Explorer continue in one context. The setting is off when absent or false. Every valid nonterminal `submit_notes` call, including one with `notes: []`, saves its notes and returns the actual receipt `{noteIds}` only. After that receipt, Explorer receives a fresh user message exactly `Keep trying, you can do it.` and continues in the same context. `solution: true` hands off a claimed complete solution early. When the context threshold is reached, the call finalizes. An empty submission at that point hands the saved notes to the coordinator with `emptySubmission: true`, asking for a different promising approach. The generic kernel submission gate still supports `emptyArgument` for other callers, while Explorer continuation does not enable it.

The preferred total-context budget remains 400,000 tokens, bounded by model capacity. Explorer reserves the selected model's maximum output tokens for finalization. The budget and reserve are separate from model capacity, input pricing thresholds, and cumulative billed usage. A gated `incomplete.max_messages` recovery receives the same fresh user feedback without changing its `maxRecoveries` allowance or accounting. Other transient retries retain their existing behavior.

## Verification and compatibility

Support is validated from declared note IDs and one shared transitive-closure calculation. The source, correctness, requirements, and reconstruction verifiers retain separate obligations. `INCONCLUSIVE` preserves the uncertainty as unverified evidence and allows independent work and later Explorer turns to continue. A caller's external verification remains an attestation and does not replace the normal acceptance checks.

The current release uses workflow schema 36 and execution-contract schema 9. The kernel journal schema and `run TASK.json CAMPAIGN.db SETTINGS.json` arguments remain unchanged. Preserve campaigns created by the published Elenx 0.9.4 and Solver 0.35.0 packages with those matching packages. That published release used workflow schema 24 and execution-contract schema 8, and its version provenance remains unchanged.
