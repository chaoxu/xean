# Elenx 0.9.4 and elenx-solve 0.35.0

These notes describe the published `v0.9.4` packages. For current source behavior and compatibility, see the [Solver README](../../packages/solve/README.md) and [kernel specification](../../SPEC.md).

Another agent can now guide an active or paused solver campaign through a durable CLI command. Advice reaches one future Explorer turn and keeps the same input across retries. Coordinator recommendations and external advice share the Explorer's `explorerGuidance` field, while the original task remains the objective.

Both packages are licensed under MIT. The release includes versioned package archives and [installation instructions](../../packages/solve/docs/installation.md) for OpenAI API accounts and Codex subscriptions, with no Fleet services required.

- `guide --id ID CAMPAIGN.db GUIDANCE.txt` records idempotent advice. `inspect --include-guidance` reports delivery.
- Inspection derives phase, notes, calls, guidance, and accounting from the same journal snapshot, fixing inconsistent reports during concurrent writes.
- Support closure has one Cozo implementation shared by validation, verifier context, window calculation, and export. Guidance interval selection and duplicate text schemas are also consolidated.
- Public examples and the agent guide cover starting, inspecting, guiding, resuming, and exporting campaigns.

## Compatibility

Solver 0.35.0 uses workflow schema 24. It replaces the coordinator's `objective` with next-turn `explorerGuidance` and removes persistent settings-level guidance. Use matching historical implementations for older workflow campaigns. The simplification preserves schema-24 prompt bytes.

The kernel remains at journal schema 5. The solver's execution contract and report remain at schema 8, with the same `run TASK.json CAMPAIGN.db SETTINGS.json` arguments and terminal outcomes. Role schemas, verdict policy, and stopping rules retain the behavior of workflow schema 24.
